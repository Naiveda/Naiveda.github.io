一句话结论：**以你现在的 Hugo + PaperMod + Pages CMS + GitHub Actions 博客为主线，可以把所需知识整理成 8 个模块，并沿“入门 → 会用 → 能改 → 能独立搭建”逐层升级。**

# 知识地图


| 知识模块 | ① 入门：知道是什么 | ② 会用：能完成任务 | ③ 能改：能定位和修改 | ④ 能独立搭建：理解整体系统 |
| -------------------------- | --------------------------------- | ----------------------------------------------------------------- | ------------------------------------------ | ------------------------------------ |
| 🌐 **Web 基础** | 知道 HTML、CSS、JS、URL、HTTP、HTTPS 是什么 | 能看懂网页结构，知道浏览器访问网站的大致过程 | 能用开发者工具检查元素、样式、网络请求 | 能解释用户输入 URL 后，从 DNS 到服务器再到浏览器渲染的完整过程 |
| 📝 **Markdown 与内容模型** | 会写标题、列表、链接、图片、代码块 | 会写 Front Matter，使用 title/date/tags/draft | 能设计文章、笔记、标签、隐藏状态等字段 | 能设计适合长期维护的内容模型与目录结构 |
| ⚙️ **Hugo** | 理解“Markdown → 静态 HTML” | 会 `hugo server -D`、`hugo --gc --minify`，知道 content/static/layouts | 会写模板、Section、Taxonomy、RSS、搜索索引 | 能从空目录创建 Hugo 站点并自行设计模板体系 |
| 🎨 **HTML / CSS / 前端设计** | 能识别标签、class、CSS 属性 | 会改字体、间距、颜色、宽度、响应式 | 会自己写首页布局、列表、移动端样式、深色模式适配 | 能从设计稿独立实现完整博客界面 |
| 🧩 **主题与模板机制** | 知道 PaperMod 是 Hugo Theme | 会配置 PaperMod 参数 | 理解 Hugo template lookup，能用 `layouts/` 覆盖主题 | 能自己设计一套主题架构，并控制升级兼容 |
| 🌱 **Git / GitHub** | 理解 repository、commit、branch | 会 status/add/commit/pull/push | 会处理冲突、rebase、branch、submodule、回退 | 能设计稳定的多人/多端版本管理流程 |
| 🚀 **GitHub Actions / 部署** | 知道 CI/CD 和 GitHub Pages 是什么 | 能看懂 Action 成功或失败 | 能修改 workflow、Hugo 版本、构建命令并读日志 | 能独立设计“提交→测试→构建→部署”的流水线 |
| 🗂️ **CMS / 信息架构** | 理解 CMS、文章、笔记、标签、归档 | 会用 Pages CMS 发文章、传图片 | 会配置 `.pages.yml` collection、字段、文件名规则 | 能根据知识管理目标设计整套数字花园信息架构 |

# 一张更直观的路线图

```
                           搭建个人博客
                                │
        ┌───────────────────────┼───────────────────────┐
        │                       │                       │
     内容层                  网站层                  工程层
        │                       │                       │
  Markdown / Front Matter    HTML / CSS             Git
  文章 / 笔记 / 标签         Hugo Template          GitHub
  信息架构                   PaperMod               Actions
  Pages CMS                  响应式设计             Pages
        │                       │                       │
        └───────────────────────┼───────────────────────┘
                                │
                            完整发布系统
                                │
             内容 → GitHub → 构建 → 部署 → 浏览器
```

你现在其实已经跨过了纯“入门阶段”，大致处于：

```
Web 基础             ██░░  会用
Markdown             ███░  能改
Hugo                 ██░░  会用 → 能改
HTML / CSS           ██░░  会用
PaperMod             ███░  能改
Git / GitHub         ██░░  会用
GitHub Actions       ██░░  会用
Pages CMS            ███░  能改
信息架构             ███░  能改
```

也就是说，**你目前最大的知识缺口不是“怎么把博客跑起来”，而是理解为什么它能跑起来。**

# Level 1｜入门：先建立正确的脑内模型

这一阶段目标不是背命令，而是回答：

> 我的博客到底是怎么从 Markdown 变成网页的？

必须理解这条链：

```
你写 Markdown
     ↓
content/posts/*.md
     ↓
Hugo 读取 Front Matter + Markdown
     ↓
PaperMod / layouts 提供 HTML 模板
     ↓
CSS 控制外观
     ↓
生成 public/*.html
     ↓
GitHub Pages 提供这些静态文件
     ↓
浏览器显示网页
```

同时理解 Pages CMS：

```
Pages CMS
     ↓
其实是在帮你修改 Markdown
     ↓
提交到 GitHub
```

它本身不是网站服务器。

而 GitHub Actions：

```
GitHub 收到新 commit
        ↓
启动一台临时 Linux 环境
        ↓
安装 Hugo
        ↓
运行 hugo
        ↓
得到静态网页
        ↓
部署 GitHub Pages
```

把这三个模型吃透，博客的大框架就明白了。

# Level 2｜会用：达到“日常不需要别人帮忙”

这一阶段应该能独立完成：

```
写文章
上传图片
修改标签
发布笔记
本地预览
修改简单配置
提交 Git
检查 Actions
定位普通构建错误
```

需要熟悉的命令其实不多。

Git：

```
git status
git pull --rebase
git add .
git commit -m "message"
git push
```

Hugo：

```
hugo server -D
hugo --gc --minify
```

核心目录：

```
content/       内容
static/        静态资源
assets/        CSS 等处理资源
layouts/       自定义模板
themes/        第三方主题
hugo.yaml      全站配置
.pages.yml     CMS 配置
.github/       自动部署
```

做到这里，已经足够长期运营个人博客。

# Level 3｜能改：这是你接下来最值得进入的阶段

“能改”和“会用”的最大区别是：

> 不再只知道改哪个参数，而是知道应该去哪里找。

例如首页不好看。

入门者：

```
找教程 → 复制代码
```

会用者：

```
知道应该改 CSS
```

能改者：

```
先判断：

首页由哪个模板生成？
    ↓
layouts/home.html

这个元素是什么 class？
    ↓
Chrome F12

样式来自哪里？
    ↓
PaperMod CSS / custom.css

应该覆盖主题还是修改主题？
    ↓
覆盖
```

这个阶段要重点掌握四个能力。

### ① 看懂 HTML

看到：

```
<article class="home-post-item">
    <h3 class="home-post-title">
        <a href="/posts/test/">标题</a>
    </h3>
</article>
```

能马上理解：

```
article
 └─ h3
     └─ a
```

### ② 看懂 CSS

看到：

```
.home-post-item {
    display: grid;
    grid-template-columns: 48px 100px 1fr;
}
```

知道：

> 这是一个三列 Grid 布局。

### ③ 看懂 Hugo Template

例如：

```
{{ range site.RegularPages }}
    {{ .Title }}
{{ end }}
```

能理解：

> 遍历所有内容页面，然后输出标题。

进一步：

```
{{ where site.RegularPages "Section" "posts" }}
```

理解：

> 只筛选 posts。

### ④ 会查错误来源

例如：

```
搜索重复
```

思路应该变成：

```
搜索页面
↓
JS
↓
index.json
↓
Hugo 搜索模板
↓
发现 Scratch 累积
```

这就真正进入“开发”阶段了。

# 这 8 块知识之间不是平行关系

真正的依赖关系大概是：

```
Web 基础
   │
   ├── HTML
   │     │
   │     └── Hugo Template
   │
   ├── CSS
   │     │
   │     └── PaperMod 定制
   │
   └── HTTP / URL
         │
         └── GitHub Pages


Markdown
   │
   ├── Front Matter
   │
   ├── Hugo Content
   │
   └── Pages CMS


Git
 │
 └── GitHub
       │
       └── GitHub Actions
             │
             └── GitHub Pages
```

所以最合理的学习顺序并不是：

```
Git → Hugo → CSS → GitHub Actions → HTML……
```

而是：

```
① Web 基础
      ↓
② HTML + CSS
      ↓
③ Markdown + Hugo
      ↓
④ Git + GitHub
      ↓
⑤ GitHub Actions
      ↓
⑥ Hugo Template
      ↓
⑦ Pages CMS
      ↓
⑧ 信息架构 / 数字花园
```

# 针对你的学习优先级

你现在已经把博客真正搭起来了，所以不建议再从“HTML 第一章是什么标签”这种方式重新学一遍。

更适合采用：

> **遇到实际博客问题 → 学对应知识 → 马上修改自己的网站。**

接下来可以按这个顺序补。

### 第一优先级：HTML + CSS

目标：

> 我看到网页，基本知道它为什么长这样。

重点：

```
HTML DOM
class
盒模型
margin / padding
width / max-width
display
flex
grid
position
媒体查询
CSS 变量
```

学完直接改：

```
Naiveda 首页
```

这是反馈最快的一块。

---

### 第二优先级：Hugo Template

目标：

> 我可以自己控制网站显示哪些内容。

重点：

```
{{ .Title }}
{{ .Content }}

range
where
with
if

site.RegularPages
.Section
.Params
.RelPermalink

partial
layout lookup
```

学完你就能自己做：

```
最新文章
最近笔记
精选内容
年度归档
标签统计
站点统计
```

---

### 第三优先级：Git

目标：

> 不怕把博客改坏。

重点：

```
working tree
staging
commit
HEAD
branch
remote

pull
push
merge
rebase

diff
restore
revert
```

特别是理解：

```
工作区
↓ git add
暂存区
↓ git commit
本地仓库
↓ git push
远端仓库
```

一旦搞明白，Git 会突然没那么玄学。

### 第四优先级：GitHub Actions

不用学得特别深。

只需理解：

```
on:
jobs:
steps:
uses:
run:
```

以及：

```
事件
↓
Workflow
↓
Job
↓
Step
```

能看懂自己的部署 YAML 就够了。

# 最终能力标准

可以用四句话判断自己处在哪个等级。

### 入门

> “我知道博客大概是怎么工作的。”

### 会用

> “只要网站没坏，我自己能正常维护和发文章。”

### 能改

> “有新需求，我知道应该修改哪个层面，并能自己查文档解决。”

### 能独立搭建

> “即使把当前项目删掉，我也能重新设计并搭建一套类似系统。”

---

你现在最适合的目标不是一下冲到第四级，而是先达到一个非常实用的状态：

> **HTML/CSS、Hugo、Git 三块进入“能改”，其余保持“会用”。**

一旦这三块打通，你以后再看 `qianling.pw`、Owen Young 或其他博客时，就会从“这个网站挺好看”逐渐变成：

> “这个首页应该是自定义模板；这里用了两列 Grid；内容应该按 section 筛选；Archive 是另一个信息入口；这个效果我也能实现。”

这就是从**使用工具**走向**理解系统**的分界线。
